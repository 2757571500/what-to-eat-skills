# what-to-eat-visualize

## 何时使用此 Skill

可视化能力 - 启动本地服务器并在浏览器中打开菜品库页面，提供直观的卡片式浏览体验。


## 何时使用此 Skill

当用户意图属于"可视化"时，调用此 Skill。

**触发条件**:
- 用户请求打开菜品库网页（"打开看看"、"看看菜品库"）
- 用户提到"网页"、"浏览器"、"可视化"、"界面"
- 用户想直观浏览所有菜品
- 用户需要搜索或筛选菜品


## 1. 启动可视化服务器

**CLI 命令**:
```bash
bash ../../scripts/visualize.sh [端口]
```

**默认端口**: 3000

**执行步骤**:
1. 检查端口是否已被占用
2. 如果被占用，询问用户是否使用其他端口或停止占用进程
3. 执行 `bash ../../scripts/visualize.sh` 启动服务器
4. 等待服务器就绪
5. 打开浏览器访问 http://localhost:3000

**示例对话**:

```
用户: "打开看看"
→ 检查端口 3000 是否可用
→ 执行: bash ../../scripts/visualize.sh 3000
→ 等待服务器启动
→ 打开浏览器: http://localhost:3000
→ 回复: "🌐 菜品库可视化页面已启动\n   浏览器已打开 http://localhost:3000\n   按 Ctrl+C 停止服务器"
```

---


## 2. 端口冲突处理

**检测端口占用**:
```bash
# Windows
netstat -ano | findstr :3000

# macOS/Linux
lsof -i :3000
```

**处理策略**:

```
场景 1: 端口未被占用
→ 直接启动服务器

场景 2: 端口已被占用，但不确定是否是本系统
→ 询问: "端口 3000 已被占用，是否使用其他端口？\n   1. 使用端口 3001\n   2. 使用端口 8080\n   3. 停止占用进程（需确认 PID）"

场景 3: 用户选择其他端口
→ 执行: bash ../../scripts/visualize.sh [新端口]
→ 打开浏览器: http://localhost:[新端口]

场景 4: 用户选择停止占用进程
→ 终止占用进程
→ 启动服务器
```

---


## 3. 服务器管理

**启动服务器**:
```bash
bash ../../scripts/visualize.sh
```

**停止服务器**:
- 在终端按 `Ctrl+C`
- 或直接关闭终端窗口

**重启服务器**:
- 停止（Ctrl+C）后重新启动

**示例对话**:

```
用户: "打开浏览器"
→ 检测到服务器已在运行
→ 回复: "服务器已在运行，打开浏览器 http://localhost:3000"
→ 打开浏览器
```

---


## 4. 浏览器自动化

**根据操作系统选择合适的打开方式**:

```bash
# Windows
start http://localhost:3000

# macOS
open http://localhost:3000

# Linux
xdg-open http://localhost:3000
```

**如果浏览器打开失败**:
```
→ 回复: "服务器已启动，但浏览器打开失败\n   请手动访问 http://localhost:3000"
```

## 可视化功能说明

启动服务器后，用户可以在浏览器中使用以下功能：


## 卡片视图

- 每道菜品以卡片形式展示
- 显示菜品名称、分类、用时、难度
- 显示距上次食用天数


## 搜索功能

- 按名称搜索菜品
- 按食材关键词搜索
- 实时过滤结果


## 分类筛选

- 按分类筛选（家常菜/川菜/凉菜/汤/主食/粤菜/甜品/其他）
- 快速浏览特定分类的菜品


## 待确认菜品

- 查看待确认队列
- 直接在 Web 界面确认/拒绝菜品


## 空状态提示

- 菜品库为空时的友好提示
- 待确认列表为空时的提示

## 常见错误场景

1. **端口被占用**
   ```
   → 回复: "❌ 端口 3000 已被占用\n   是否使用其他端口？\n   1. 端口 3001\n   2. 端口 8080"
   ```

2. **服务器启动失败**
   ```
   → 执行: bash ../../scripts/visualize.sh 3000
   → 错误: "❌ 服务器启动失败\n   请检查端口是否可用，或 node 是否正常运行"
   ```

3. **数据文件缺失**
   ```
   → 服务器启动
   → 用户打开浏览器
   → 页面提示: "无法加载数据文件，请确保 data/dishes.json 存在"
   ```


## 注意事项

- **服务器持续运行**：启动后保持运行，直到用户按 Ctrl+C 或关闭终端
- **端口默认 3000**：如果被占用，建议用户选择其他端口
- **浏览器自动打开**：尝试自动打开，失败时提供手动访问地址
- **服务器独立运行**：不影响 CLI 的其他操作，两者并行工作
- **数据实时加载**：Web 页面通过 Fetch API 加载 JSON，每次刷新显示最新数据


## 注意事项

- **自包含部署包**：本 Skill 已包含完整的运行时脚本
- **路径引用**：使用相对路径引用脚本（`../../scripts/`）
- **数据文件**：首次使用需要复制 `data/example.json` 到 `data/dishes.json`
