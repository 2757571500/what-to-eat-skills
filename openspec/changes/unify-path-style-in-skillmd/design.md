# 技术设计：统一 Skill 文档路径风格

## Context

### 背景

在 `fix-skill-dispatch-mechanism` 变更中，我们修正了 Skill 分发机制的文档，统一采用"完整路径"风格（`bash what-to-eat-collect/scripts/collect.sh`）。目前已完成的文档包括：
- ✅ `what-to-eat-skills/SKILL.md`（总控入口）
- ✅ `what-to-eat-skills/docs/*.md`（4 个用户文档）

但 `CLAUDE.md`（项目根目录的开发者文档）仍使用"cd + 相对路径"风格，与整体文档风格不一致。

### 当前状态

**已统一为"完整路径"的文档**：
```
what-to-eat-skills/
├── SKILL.md               ← 完整路径 ✅
└── docs/
    ├── collect.md         ← 完整路径 ✅
    ├── manage.md          ← 完整路径 ✅
    ├── recommend.md       ← 完整路径 ✅
    └── visualize.md       ← 完整路径 ✅
```

**未统一的文档**：
```
E:\Code\what-to-eat-skills/
└── CLAUDE.md              ← cd + 相对路径 ❌
```

### 约束条件

- **文件范围**：仅修改 `E:\Code\what-to-eat-skills\CLAUDE.md`
- **功能不变**：所有命令的实际执行效果不变
- **风格统一**：与 `SKILL.md` 和 `docs/*.md` 保持一致
- **向后兼容**：不影响现有用户的使用习惯

## Goals / Non-Goals

### Goals

1. **统一文档风格**：`CLAUDE.md` 与 `SKILL.md`、`docs/*.md` 保持一致
2. **提升易用性**：用户可以从任何文档复制粘贴命令直接使用
3. **降低理解成本**：一致的路径风格减少用户困惑

### Non-Goals

1. ❌ **不修改任何脚本代码**：`.sh`、`.js` 文件保持不变
2. ❌ **不改变命令执行逻辑**：仅修改文档描述
3. ❌ **不修改目录结构**：项目结构保持不变
4. ❌ **不影响脚本实际运行**：脚本本身不依赖文档风格

## Decisions

### 决策：CLAUDE.md 采用"完整路径"风格

**决策**：将 `CLAUDE.md` 中的所有命令示例从"cd + 相对路径"改为"完整路径"。

**理由**：
- ✅ **文档一致性**：与 `SKILL.md` 和 `docs/*.md` 保持完全一致
- ✅ **提升易用性**：用户可以从任何文档复制命令，无需调整格式
- ✅ **符合项目规范**：确立"完整路径"为项目的唯一标准路径风格
- ✅ **降低维护成本**：未来只需维护一种路径风格

**替代方案**：

| 方案 | 描述 | 为什么不用 |
|------|------|-----------|
| A. 保持现状 | CLAUDE.md 用"cd + 相对路径"，其他文档用"完整路径" | ❌ 文档风格不统一<br>❌ 增加用户困惑<br>❌ 不符合文档一致性原则 |
| B. 全部改为"cd + 相对路径" | SKILL.md、docs/*.md、CLAUDE.md 全部统一 | ❌ 需要修改已完成的文档<br>❌ "cd + 相对路径"对用户不够友好<br>❌ 返工成本高 |
| **C. 全部统一为"完整路径"** | **所有文档统一** | ✅ **一致性最佳**<br>✅ **用户友好**<br>✅ **与已完成文档保持一致** |

### 路径计算说明

**从项目根目录执行**：
```bash
# 项目根目录: E:\Code\what-to-eat-skills
cd E:\Code\what-to-eat-skills

# 完整路径格式
bash what-to-eat-collect/scripts/collect.sh add "麻婆豆腐"
```

**路径解析**：
```
E:\Code\what-to-eat-skills\              ← 当前目录（pwd）
├── what-to-eat-collect\                 ← 目标 Skill
│   └── scripts\
│       └── collect.sh                  ← 目标脚本
```

**与"cd + 相对路径"的对比**：
```bash
# 完整路径（推荐）
bash what-to-eat-collect/scripts/collect.sh add "麻婆豆腐"

# cd + 相对路径（废弃）
cd what-to-eat-collect && bash scripts/collect.sh add "麻婆豆腐"
```

## Risks / Trade-offs

### 风险 1：开发者习惯改变

**风险**：熟悉"cd + 相对路径"的开发者需要适应新风格。

**缓解措施**：
- 新风格更直观，学习成本低
- 文档一致性带来的长期收益大于短期适应成本

### 权衡 1：命令长度

**权衡**："完整路径"比"cd + 相对路径"更长。

**为什么接受**：
- 路径长度增加约 25 个字符，可接受
- 换行和代码块格式可以改善可读性
- 用户体验（复制粘贴即用）比命令长度更重要

### 权衡 2：CLAUDE.md 的特殊定位

**权衡**：CLAUDE.md 是开发者文档，是否应该采用不同的风格？

**为什么统一**：
- 文档一致性原则：所有文档采用相同风格
- 开发者也是用户，应该享受一致的体验
- "完整路径"对开发者同样友好

## Open Questions

### 问题 1：是否保留部分"cd + 相对路径"示例？

**场景**：某些开发者工作流可能确实需要 cd（如调试特定 Skill）。

**当前决策**：全部统一为"完整路径"，不保留特殊示例。

**理由**：
- "完整路径"可以满足所有场景
- 保留特殊示例会破坏一致性
- 如有特殊需求，可在具体场景说明中单独解释
