# what-to-eat-collect

## 何时使用此 Skill

菜品收集能力 - 支持手动录入菜品、查看待确认列表、确认/拒绝菜品、AI 自动生成新菜品。所有菜品先进入待确认队列，经人工确认后正式入库。


## 何时使用此 Skill

当用户意图属于"菜品收集"时，调用此 Skill。

**触发条件**:
- 用户添加/录入新菜品
- 用户查看待确认列表
- 用户确认或拒绝菜品
- 用户请求 AI 生成新菜品
- 用户提到"待确认"、"pending"等关键词


## 1. 手动录入菜品

**用户意图**: 用户想添加一道新菜品

**CLI 命令**:
```bash
bash ../../scripts/collect.sh add <菜名> [--category 分类] [--tags 标签1,标签2] [--ingredients 食材1,食材2] [--prepTime 分钟] [--difficulty 难度]
```

**执行步骤**:
1. 解析用户输入，提取菜品名称
2. 识别可选参数（分类、标签、食材、用时、难度）
3. 执行 CLI 命令
4. 告知用户菜品已添加到待确认列表

**示例对话**:

```
用户: "加个麻婆豆腐"
→ 执行: bash ../../scripts/collect.sh add "麻婆豆腐"
→ 回复: "已添加「麻婆豆腐」到待确认列表"

用户: "加个番茄炒鸡蛋，分类是家常菜，15分钟，简单"
→ 执行: bash ../../scripts/collect.sh add "番茄炒鸡蛋" --category 家常菜 --prepTime 15 --difficulty 简单
→ 回复: "已添加「番茄炒鸡蛋」到待确认列表"
```

**参数说明**:

| 参数 | 说明 | 示例 |
|------|------|------|
| `--category` | 分类（家常菜/川菜/凉菜/汤/主食/粤菜/甜品/其他） | `--category 川菜` |
| `--tags` | 标签，逗号分隔 | `--tags 麻辣,下饭菜` |
| `--ingredients` | 主要食材，逗号分隔 | `--ingredients 豆腐,肉末` |
| `--prepTime` | 制作时间（分钟） | `--prepTime 15` |
| `--difficulty` | 难度（简单/中等/困难） | `--difficulty 简单` |

## 2. 查看待确认列表

**用户意图**: 用户想查看待确认的菜品列表

**CLI 命令**:
```bash
bash ../../scripts/collect.sh list-pending
```

**执行步骤**:
1. 执行 CLI 命令
2. 格式化输出结果（编号、菜品名称、分类、用时、难度等）
3. 如果列表为空，提示用户当前没有待确认菜品

**示例对话**:

```
用户: "看看有哪些待确认的"
→ 执行: bash ../../scripts/collect.sh list-pending
→ 回复:
  📋 待确认菜品 (2 道):

    0. 水煮鱼 | 川菜 | 25分钟 | 中等
      标签: 麻辣,下饭菜
      食材: 鱼肉,豆芽

    1. 糖醋排骨 | 家常菜 | 30分钟 | 中等
      标签: 酸甜,下饭菜
      食材: 排骨
```

## 3. 确认菜品

**用户意图**: 用户确认某道待确认菜品，将其加入正式菜品库

**CLI 命令**:
```bash
bash ../../scripts/collect.sh confirm <名称|索引>
```

**执行步骤**:
1. 从用户输入中提取菜品名称或索引（0-based）
2. 执行确认命令
3. 告知用户操作结果

**示例对话**:

```
用户: "确认第 2 个"
→ 解析索引: 1 (0-based)
→ 执行: bash ../../scripts/collect.sh confirm 1
→ 回复: "已确认「糖醋排骨」→ 加入菜品库"

用户: "确认水煮鱼"
→ 执行: bash ../../scripts/collect.sh confirm "水煮鱼"
→ 回复: "已确认「水煮鱼」→ 加入菜品库"
```

**注意事项**:
- 索引从 0 开始（与 list-pending 显示一致）
- 支持菜品名称或索引两种方式

**示例对话**:

## 6. AI 自动生成菜品

**用户意图**: 用户希望 AI 自动生成一批新菜品到待确认队列

**CLI 命令**:
```bash
bash ../../scripts/collect.sh auto-generate [--count N]
```

**参数**:
- `--count N`: 生成数量，默认 3 道

**执行步骤**:
1. 解析用户输入中的数量参数（如"生成 5 道"→ count=5）
2. 执行自动生成命令
3. 展示生成的菜品列表
4. 建议用户查看待确认列表或直接确认

**示例对话**:

```
用户: "生成 3 道新菜"
→ 执行: bash ../../scripts/collect.sh auto-generate --count 3
→ 回复:
  🤖 AI 生成策略: 种子库采样 + 变体组合

    1. 鱼香肉丝 | 川菜 | 20分钟 | 中等
    2. 蒜蓉西兰花 | 家常菜 | 10分钟 | 简单
    3. 红烧牛腩 | 家常菜 | 60分钟 | 困难

  已添加到待确认列表，你可以:
  - 查看待确认: "看看有哪些待确认的"
  - 确认全部: "全部确认"
  - 拒绝菜品: "拒绝第 X 个"

用户: "生成新菜"
→ 执行: bash ../../scripts/collect.sh auto-generate --count 3
→ 回复: （同上，使用默认数量 3）
```

## 常见错误场景

1. **菜品已存在**
   ```
   用户: "加个麻婆豆腐"
   → 执行: bash ../../scripts/collect.sh add "麻婆豆腐"
   → 错误: "❌ 菜品「麻婆豆腐」已存在"
   ```

2. **索引越界**
   ```
   用户: "确认第 5 个"
   → 执行: bash ../../scripts/collect.sh confirm 4
   → 错误: "❌ 索引越界"
   ```

3. **参数格式错误**
   ```
   用户: "加个菜，分类是 abc"
   → 执行: bash ../../scripts/collect.sh add "菜" --category abc
   → 错误: "❌ 无效的分类"
   ```


## 注意事项

- **所有菜品先入库，后确认**：这是系统的核心工作流，不可绕过
- **索引从 0 开始**：与 list-pending 显示一致，用户可能困惑，需清晰说明
- **确认后不可撤回**：菜品一旦确认到正式库，需通过 delete 命令删除
- **参数可选**：手动录入时，用户只需提供菜品名称，其他字段可以后续补充


## 注意事项

- **自包含部署包**：本 Skill 已包含完整的运行时脚本
- **路径引用**：使用相对路径引用脚本（`../../scripts/`）
- **数据文件**：首次使用需要复制 `data/example.json` 到 `data/dishes.json`
